# gates: the acceptance oracles this workspace is measured against

This file exists so that "ported" and "done" mean a command that exited 0, not an
opinion. Every claim in `docs/STATUS.md` names one of these.

## Tier 1: the two suites that define the storage contract

Named in PLAN.md section 2 as the acceptance oracle for every storage crate.
Port these first, into `dxdb-testkit`, and every storage after that is plumbing.

| Upstream | Lines | dxdb target | Gate |
| --- | --- | --- | --- |
| `test/unit/rx-storage-implementations.test.ts` | 4,115 | `crates/dxdb-testkit/` | `make gate-storage` |
| `test/unit/rx-storage-query-correctness.test.ts` | 2,663 | `crates/dxdb-testkit/` | `make gate-query-correctness` |

Both are Apache-2.0 and are ports, not clean-room work. Every ported test names
the upstream file and line it came from.

## Tier 2: the cross-language oracle

`testdata/vectors/*.json` hold expected outputs generated by running upstream
RxDB in Node. This is what makes "behaviourally identical" assertable rather
than aspirational. PLAN.md section 7.2 lists the vector families:

- index strings for every schema/field/value combination in upstream fixtures
- schema hashes for every fixture schema
- normalised queries for a generated query corpus
- `categorizeBulkWriteRows` outputs for generated write sequences
- replication transcripts with resulting checkpoints and resolved document states

Gate: `make vectors-check` regenerates them and fails on drift.

## Tier 4: property and fuzz

- `proptest` on the selector matcher, agreed against JS oracle vectors.
- Differential fuzzing of the storage contract: per-document atomicity,
  monotonic revisions, no lost writes, `count` == `query().len()`.
- `cargo-fuzz` on the schema/index path, which parses untrusted JSON.

## Tier 5: performance

A criterion bench per storage, a JSON result file per run, thresholds in CI,
numbers recorded in `docs/BENCHMARKS.md`. No "faster than X" sentence ships
without a number from that file.
